# DH Tracker — план доработок

## Принципы

- Все координаты в мире — **в метрах**. 1 клетка SRD (5 ft) ≈ 1.5 м.
- Игра без сетки. Привязка к сетке 0.5 м — только в редакторе.
- **Карта — отдельная сущность**, энкаунтер ссылается на карту (одну локацию используют несколько энкаунтеров).
- Картинки (фоны, пропсы) — **только по публичному URL**, в хранилище приложения не кладутся. На экран игроков уходит URL.
- Все данные экспортируются в **JSON** с полем `version`.

## Целевая модель данных

```
Map {
  id, name,
  background: { url, pxPerMeter, offset: { x, y } } | null,
  walls: [{ id, points: [{ x, y }, ...] }],                 // ломаная
  rooms: [{ id, name, kind: 'room' | 'building',
            polygon: [{ x, y }, ...] }],
  props: [{ id, templateId?, name, imageUrl, x, y, size, rotation,
            states: [{ name, imageUrl? }], state: 0 }],
}

PropTemplate { id, name, imageUrl, size, states: [{ name, imageUrl? }] }   // библиотека пропсов

Encounter {
  id, name, mapId,
  adversaries: [Adversary],          // встроенные монстры (пришли с импортом энкаунтера)
  placements: [{ ref: { lib: id } | { local: id }, label, x, y, size }],
  spawnPoints: [{ x, y }],           // точки спауна PC
}

ExportFile { version, adversaries[], propTemplates[], maps[], encounters[] }
```

Состояние текущей сессии на доске (позиции токенов, открытые комнаты, состояния пропсов в бою) хранится отдельно от карты — карта переиспользуется.

## Фаза 1 — Масштаб и UI

- [x] Перевести мировые координаты в метры (константа `PX_PER_M` только для отрисовки). Текущую доску при миграции очистить.
- [x] Кольца дистанций: Melee 1.5 м, Very Close 4.5 м, Close 9 м, Far 18 м. Very Far — подпись «> 18 м», без кольца. Дистанция меряется от края токена.
- [x] Подписи колец и легенды — точные значения в метрах вместо прозовых диапазонов SRD (`DIST_LABEL`).
- [x] Токен: диаметр 1.5 м. Поле `size` (множитель) у токена и у монстра в библиотеке.

## Фаза 2 — Экспорт / импорт JSON

- [ ] Формат `ExportFile` с `version`; миграция старых версий при импорте.
- [ ] Экспорт: всё (бэкап) или выбранное — монстры, энкаунтеры, карты, шаблоны пропсов.
- [ ] Энкаунтер экспортируется самодостаточным: его карта и все используемые монстры (включая библиотечные) копируются в файл, монстры — в `encounter.adversaries`.
- [ ] **Импорт энкаунтера:** его монстры загружаются внутрь энкаунтера, **в библиотеку не попадают**. Карта добавляется в список карт.
- [ ] **Импорт монстра в библиотеку** при совпадении имени — диалог: **Заменить / Переименовать / Отменить**. Тот же диалог для карт и шаблонов пропсов.
- [ ] Импорт перенумеровывает id (на другом устройстве они другие).

## Фаза 3 — Карта с фоном, энкаунтеры с расстановкой

- [ ] Сущность `Map`, вкладка Maps (список, создать, удалить).
- [ ] Фон по публичному URL. Калибровка: две точки + расстояние в метрах, или ввод «px на клетку 1.5 м». Смещение фона.
- [ ] Картинка не загрузилась — видимое предупреждение, карта работает без фона.
- [ ] `Encounter`: `mapId`, `placements`, `spawnPoints`. Существующие энкаунтеры-ростеры мигрируют без карты и позиций.
- [ ] «Сохранить доску в энкаунтер»: текущие противники с позициями + отмеченные точки спауна.
- [ ] Deploy: загрузить карту → расставить противников → диалог «кто из PC на сессии» → PC встают на точки спауна по порядку (лишние — рядом с последней точкой).
- [ ] Экран игроков: отдельное сообщение `SCENE_UPDATE` (карта целиком) при смене сцены. `STATE_UPDATE` остаётся только для токенов.

> URL должен вести прямо на картинку. Ссылки «поделиться» Google Drive / Dropbox не подойдут; часть сайтов блокирует показ картинок на чужих страницах.

## Фаза 4 — Векторный редактор и пропсы

- [ ] Режимы **Edit / Play**. В Play карта не редактируется.
- [ ] Привязка к сетке 0.5 м в Edit.
- [ ] Стены — ломаные.
- [ ] Комнаты и здания — прямоугольник / многоугольник, хранятся как отдельные полигоны (нужно для фазы 5).
- [ ] **Библиотека пропсов:** шаблон = имя, URL картинки, размер, список состояний. Шаблоны входят в экспорт.
- [ ] Размещение пропсов на карте: перемещение, поворот, размер.
- [ ] **Состояния пропсов:** список состояний, у каждого опционально своя картинка (целая бочка / разбитая / горящая). В Play GM переключает состояние кликом, изменение уходит на экран игроков. Нет картинки у состояния — базовая картинка + подпись состояния.
- [ ] Картинка пропса не загрузилась — заглушка с названием.
- [ ] Выделение, перемещение, удаление объектов.
- [ ] Undo / Redo (Ctrl+Z / Ctrl+Shift+Z) — стек снимков карты в режиме Edit. *Если окажется дорого — отложить.*

## Фаза 5 — Видимость (минимальный приоритет)

- [ ] GM открывает / закрывает комнату кликом в Play.
- [ ] На экране игроков закрытые комнаты затемнены, токены и пропсы внутри не видны.
- [ ] GM видит закрытые комнаты полупрозрачными.

## Вне плана

- Динамический line of sight от токенов.
- Хранение картинок внутри приложения (IndexedDB).
